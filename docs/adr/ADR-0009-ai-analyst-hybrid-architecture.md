# ADR-0009：AI 当分析师——确定性工程 × AI 混合架构

- 状态：接受
- 日期：2026-10-16
- 依据：owner 产品方向定调（2026-10-16）+ alibaba/open-code-review 调研
  （[research-2026-10.md](../research-2026-10.md) 增补节）；部分取代
  [ADR-0003](ADR-0003-deterministic-referee-ai-advisor.md) 的 AI 职责面
  （确定性裁判与实证关原样保留）

## 决策

**AI 从"可选顾问"升级为"承重分析师"，确定性代码当裁判、同时当 AI 的供给方。**
信任模型不变：结论级判定（schema 是否一致、索引是否有效、规则是否命中）只出自
确定性代码与影子库实证，退出码永不受 AI 输出影响。改变的是 AI 的职责面——从
optimize 车道的一个候选生成器，扩展为四车道共用的判断层，做确定性规则表达不了的
语义工作（ADR-0001 承诺四"Agent 原生轻端"的兑现）。

### AI 职责面（四车道矩阵）

| 车道 | 确定性层供给 | AI 判断性工作 | 结论分级 |
|---|---|---|---|
| 变更 pack | 变更切片 + schema 上下文 + 破坏性预警 | 变更组语义评审：语句顺序风险、依赖/重命名冲突、跨语句意图问题 | AI 观点 |
| verify | 三方 diff 事实（漏执行/错执行/漂移） | 失败归因的自然语言解释与修复建议 | AI 观点 |
| lint | 规则初筛命中清单（规则注入） | 通过 lint 的残留语句语义审查——规则边际递减的长尾 | AI 观点 |
| optimize | EXPLAIN 事实 + schema 切片 | 候选生成（索引/改写）→ 影子库实证复核 | 实证已验证 / 未验证（ADR-0003 原样） |
| patrol | 漂移 / 未用索引 / 慢日志指纹 | 跨信号综合洞察叙事 | AI 观点 |

AI 产物一律两级标注：**实证已验证**（判定出自确定性代码与实测，可关联退出码）与
**AI 观点**（报告单列，永不影响退出码）。

### 交互形态分层（tools / skills / MCP / 子代理 vs 纯文本）

按"谁的模型在跑"分两条通道，按"证据从哪来"定内置通道的形态：

**通道 A（默认主通道，零密钥）：宿主 Agent 委托面。** AI 活在宿主（Claude Code /
Cursor 等），modou 不配任何模型：

- MCP 面从"1:1 映射 CLI"扩列**证据原语工具**（快照摘要 / 回放验收 / 三方 diff /
  EXPLAIN / lint 命中），每个工具有 CLI 对应物，parity 守护随之延伸（ADR-0002）；
- 随包分发 **skills 资产**（提示词模板 + 工作流说明），教宿主 Agent 组合工具完成
  数据库变更评审。skills 是文档不是代码，零依赖。

**通道 B（BYOK 内置 AI，未配置零网络）：受控多轮，纯文本传输。** 内置分析
（lint 残留评审、verify 归因、patrol 叙事、optimize 候选）采用：

- **证据由确定性流水线预取并打包进提示词**（schema 切片器只发相关库表子集、
  变更分包、规则模板注入），**不让内置 AI 自主调用工具**——OCR 的实证是
  "确定性供证据"比 agent 自主探索更稳定、更省 token、更可审计；
- 并发 = 确定性分包后的并发单轮调用（map-reduce 式），**不做内置子代理编排**；
- 输出约束为结构化格式并逐条校验，不可解析条目丢弃（现有 advisor 模式推广）；
- fail-safe 不变：超时/失败降级为"无 AI 观点"，不阻塞报告。

**内置 tool-use agent loop（AI 自主调 EXPLAIN 回读等）列为演进位，不开工。**
触发条件：评测实证表明受控多轮的质量天花板卡住某条车道时，才在
optional-dependencies 引入 agent SDK。取舍判据：agent harness 的编排复杂度、
BYOK 端点 tool-call 能力参差、fail-safe 降级复杂度，三者的代价当前均大于
"实证关已兜底质量风险"下的边际收益。

### 上下文工程是内核资产

提示词模板、schema 切片器、变更分包器、规则注入器与 SQL 解析器同规格对待：进
内核库、带类型注解、测试先行、版本可回归。AI 观点质量视为可测行为：评测集随
规则库演进，提示词或模板变更必须重跑评测（工程口径新增，见宪法）。

## 理由

- **OCR 实证**（阿里内部两年数万开发者，2026-06 开源，Apache-2.0）：同一底层模型，
  "确定性工程 × Agent"混合架构比通用 Agent 精度与 F1 更高、token 约 1/9；纯语言
  驱动（提示词裸奔）缺硬约束，表现为覆盖不全、位置漂移、质量不稳；
- **规则边际递减律**：静态规则写得越多，信噪比越差——规则库聚焦高频可判定项
  （lint 26 条起步的选型依据升级为架构口径），长尾语义判断交给 AI；
- **modou 的实证关强于 OCR 的反思模块**：OCR 对 AI 意见只能自检，modou 有影子库
  可实测——"AI 赋能 × 机器证据"是纯代码评审工具拿不出的差异化，也是 ADR-0001
  承诺二（MySQL 实证优化空白）的纵深；
- **零密钥与 AI 赋能不再矛盾**：主通道让宿主的模型干活，modou 保持零密钥可用；
  BYOK 通道是增量而非门槛——AI 赋能不以"配齐三个环境变量"为前提。

## 后果

- 宪法红线 1 表述改为"AI 当分析师"（两级结论标注），红线 4 增补委托面零密钥可用；
- lint 车道增加 AI 残留评审层、verify 增加归因解释、patrol 增加综合叙事——报告
  扩列"AI 观点"区（v0.1 冻结的结论契约只增不改）；MCP parity 清单扩列；
- 新增内核模块 `ai/`（上下文工程 + BYOK 客户端，自 optimize/advisor.py 演进收拢）；
- 新增评测负担：AI 观点质量需评测集回归，防止提示词改动静默劣化。
