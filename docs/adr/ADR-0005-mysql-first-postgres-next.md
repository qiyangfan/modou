# ADR-0005：MySQL 先行，PostgreSQL 次之

- 状态：接受
- 日期：2026-10-14
- 依据：痛点来源 + PG 侧竞品占位分析（Postgres MCP Pro 3.4k★）

## 决策

方言顺序锁定：**MySQL（含兼容系）先行，PostgreSQL 第二，其余按需求排队**。
内核所有方言相关代码经 dialect 适配层隔离，但 v0.1~v0.2 期间不承诺 PG 可用，
不为 PG 提前抽象。

## 理由

- 原始痛点来自 MySQL 生态（运维代执行 + 慢 SQL 治理），先解痛点再扩版图；
- PG 侧"AI 优化 + 实证"已被 Postgres MCP Pro 占住（HypoPG 假想索引 + DTA 算法），
  后发劣势明显；MySQL 侧完全空白，且 MySQL 无 HypoPG 等价物——实证必须真建索引，
  这既是成本也是壁垒（做出来即独有）；
- MySQL 在国内存量占比与"运维代执行"流程惯性最强，与产品定位共振。

## 后果

- 影子库按 MySQL 大版本（5.7/8.0/8.4）做版本矩阵，版本不匹配时明确报错而非静默降级；
- 大表索引实证可能需要采样子集策略，列入优化车道攻坚项；
- PG 支持立项时需重估与 Postgres MCP Pro 的差异化（错位：变更车道 + 交棒闭环）。
