# ADR-0003：确定性代码当裁判，AI 只当顾问

- 状态：接受
- 日期：2026-10-14
- 依据：产品信誉分析 + 用户工程哲学（实证真值优先）

## 决策

凡是可判定的客观事实——schema 是否一致、索引是否有效、规则是否命中——结论必须出自
确定性代码与数据库实证。AI（LLM）只承担两类职责：解释差异、生成候选建议。

**实证关（硬性）**：AI 产出的任何优化建议（索引 DDL、改写），必须在影子库真实建立/执行
并对比代价（EXPLAIN 前后对比），代价未降低的建议标"未验证"并排除出报告正文；
过不了实证关的建议一条都不许以"有效"面目出现。退出码永远不受 AI 输出影响。

## 理由

- 发布门禁场景下，不可审计的结论 = 不可用：没人敢把"AI 说没漏"当验收；
- LLM 在 SQL 领域的幻觉率不可忽视，但解释与候选生成是其强项——扬长避短；
- Postgres MCP Pro 的"假想索引实证"路线验证了"AI 建议 + 实证复核"的社区认可度。

## 后果

- 影子库基建是优化车道的前置依赖（与变更车道复用，ADR-0004/0006）；
- 报告格式必须有两级状态：实证通过（附提升数据）/ 未验证（附原因）；
- 规则引擎（确定性）先于 AI 诊断运行，命中规则的结论不需要 AI 参与。
