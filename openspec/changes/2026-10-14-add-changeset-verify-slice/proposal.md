# 提案：完成 v0.1 变更车道纵切面（pack + verify）

## Why

立项后的首个能力必须是痛点最重的一条：开发把几十条小 SQL 交给运维代执行，逐条执行繁琐、
合并易漏、漏了无人知晓。本 change 交付"打包防漏 + 执行后机器验收"的最小闭环，
同时把内核三件套（快照/回放/报告）的地基打出来——后续优化车道复用同一基建。

## What Changes

- 变更集发现与清单校验：`V<序号>__<描述>.sql` 目录 + manifest 一一对应。
- `modou pack`：按序合并为单文件、校验零遗漏、标注破坏性语句与锁风险。
- `modou verify`：读执行前后两份快照，在本地同版本 MySQL 回放变更集推导期望态，
  三方 diff 输出漏执行/错执行/历史漂移三类结论与确定性退出码。
- 快照采集脚本：只读导出线上元数据（information_schema + SHOW CREATE TABLE），
  供运维在执行前后各跑一次。
- 统一报告格式：人读文本 + 机读 JSON 双出口。

## 受影响决策

- ADR-0004：回放推导期望态，不用解析器累积终态。
- ADR-0007：变更集命名向 Flyway 靠拢。
- ADR-0008：多实例多库默认（verify 按库清单工作）。

## 不做清单（Non-goals）

- 不做 SQL 优化、lint 规则、漂移巡检（后续车道各自立 change）。
- 不做 DML 数据订正的全表比对（行数 + checksum 抽查口径见宪法）。
- 不做 MCP server 与报告 UI（v0.3/v0.4 范围）。
- 不做 PostgreSQL 支持（ADR-0005 顺序）。
