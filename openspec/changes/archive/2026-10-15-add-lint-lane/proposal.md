# 提案：v0.4 第一刀——审核车道（lint）

## Why

SOAR（小米，8.8k★）事实停滞、SQLAdvisor 停滞，Bytebase 200+ 规则锁在平台里——
MySQL 生态的现代化规则引擎无人继承（ADR-0001 承诺三）。v0.4 里程碑含三个交付物，
按宪法「一个 change 一个车道」拆三刀：lint（本 change，纯静态最快落地）→
patrol → ui。

调研结论（依据见 design.md）：SOAR 全 125 条规则中约 120 条为纯静态判定（审核
对象就是 SQL 文本/AST，不连库），首批取 26 条高频反模式即可满足判据（≥20）且
零数据库、零容器、零网络——CI 友好性最好的车道。

## What Changes

- `modou lint`：SQL 文件 / 目录 / 变更集目录 → 纯静态规则审核（AST 判定）。
- 首批规则 26 条（SOAR 高频反模式子集，清单冻结于 design.md，ID 沿用 SOAR 编号
  降低迁移心智），每条含唯一标识、级别、说明、改写建议与正反例测试。
- 可配置可跳过：配置文件开闭规则与调整数值阈值（IN 列表数、分页位移、单表索引
  数上限），命令行 `--skip-rule` 显式跳过（优先级高于配置文件）。
- 输出：人读文本 + 机读 JSON（规则标识、级别、文件与位置、消息、建议）；
  退出码 0=无命中、1=存在已启用规则命中、2=环境或输入错误。
- MCP 工具同步扩列（延续 v0.3 的 1:1 契约与 parity 守护）。
- 规则清单文档（标识/说明/示例/SOAR 对照出处），为 v1.0 文档齐备打底。

## 受影响决策

- ADR-0001：SOAR 遗产的规则继承者（产品线三）。
- ADR-0006：唯一 SQL 解析器承载规则引擎，不引入第二套解析依赖。
- ADR-0003：规则引擎是确定性裁判，先于且独立于任何 AI 诊断——本车道无 AI。

## 顺序与依赖

- 前置：v0.3（MCP parity 校验已建立，本 change 扩列工具清单）。
- 与 patrol / ui 无相互依赖，按 v0.4 排序第一个落地。

## 不做清单（Non-goals）

- 不做 schema-aware 规则（如精确隐式类型转换需列类型输入）——列为后续带
  schema 模式的扩展。
- 不做自动修复器（改写建议以文本附注输出）。
- 不做自定义规则 DSL（规则贡献走内核库代码共建，architecture.md「可共建」口径）。
- 不做需连库的检查（索引选择性、数据分布、采样页配置）。
- 不做 PostgreSQL 方言规则（ADR-0005）。
- 不做变更集 manifest 强校验（清单校验属 pack 职责，lint 只审 SQL 内容）。
