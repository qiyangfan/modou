# 设计：v0.4 本地报告 UI（薄报告层）

## 1. 架构形态（薄到什么程度）

```
modou ui --report verify-report.json [--report lint-report.json ...] [--port N]
  └─ Python 侧（内核库，非表面新逻辑）：
     报告加载与版本识别 → 本机回环 HTTP 服务 → 静态资源 + 报告 JSON 端点
  └─ 前端（ui/ 独立目录，Node 24 工具链构建）：
     构建产物静态文件，随 Python 包分发（hatch 打包包含）
```

- Python 侧职责严格限于：读报告文件、伺服静态资源、把已加载的报告 JSON 经本机
  端点给前端。不解析、不重算、不存储——「不绑定实现」的 spec 里对应的行为红线
  是「零外部请求 + 只读 + 无状态」。
- 页面在启动时经本机端点拉取报告数据后纯本地渲染；所有静态资源随包内联分发，
  无 CDN、无字体/脚本外链（spec 场景「零网络取数」的测试断言点）。

## 2. 前端工具链与分发

- 工具链：Node 24（家族 web 门禁标准，CI ui job 已预留条件跳过，本 change 激活），
  Vite + TypeScript；框架从轻（默认 Preact 或无框架模板）——若实现期选型偏离
  须补 ADR，不静默换重型依赖。
- 分发：`ui/` 构建产物（dist）进 Python 包（hatch build targets 包含产物目录），
  `uv tool install modou` 后 `modou ui` 开箱即用，运行期不要求 Node 存在。
- ui 门禁：typecheck / lint / test（组件级）三件，接入既有 CI ui job 的
  hashFiles 条件（ui/ 落地后自动生效，不再跳过）。

## 3. 安全与生命周期

- 绑定：默认且仅允许回环地址；提供绑定参数仅为端口让位——非回环绑定值直接
  拒绝（退出码 2 + 英文错误）。报告内容含生产 schema，回环是数据不出本地的
  最后一道闸（红线 4 的 UI 侧落地）。
- 静态资源伺服：仅伺服包内产物目录，不伺服任意路径（防目录穿越）。
- 生命周期：Ctrl-C / SIGINT 干净退出（退出码 0）；输入报告不存在/不可读/
  版本未知 → 退出码 2，错误消息列明支持的报告类型与版本清单。
- 启动即开浏览器（lazygit 模式）；`--no-open` 跳过（无头/远程终端场景）。

## 4. 视图契约（消费 formats.md 冻结格式）

| 视图 | 数据源 | 关键呈现 |
|---|---|---|
| 验收 | verify 报告（report_version=1） | 按库分组，三类结论条目 + 维度明细（期望/实际对照） |
| 优化 | optimize 报告（v0.2 契约） | 建议两级状态（实测提升/未验证）、前后代价与扫描行数对比 |
| 审核 | lint 报告 | 命中清单（标识/级别/位置/建议），按级别分组 |
| 巡检 | patrol 报告 | 漂移三类 / 未用索引分层 / 慢日志聚合榜 |

- 版本识别：报告 kind + version 双字段；未知组合 → 明确报错（向前演进靠版本
  门禁，不靠猜）。
- 多报告同开：多 `--report` 参数 → 侧栏切换（跨车道对照是真实用法：验收结论
  旁边看慢 SQL 建议）。

## 5. 测试策略

- Python 侧单测：报告加载/版本门禁/回环绑定拒绝/静态资源伺服边界。
- 前端组件测试（Node 24 门禁内）：四类视图对样例报告的渲染断言。
- 零外链断言：构建产物扫描（无 http(s) 外链资源引用）作为发布前测试。
- 端到端冒烟：起服务 → 请求页面与报告端点 → 断言内容与无监听外地址 → 干净退出。
