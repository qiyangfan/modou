# 提案：v0.4 第三刀——本地报告 UI（薄报告层）

## Why

diff 结论、EXPLAIN 前后对比、命中清单是人要「看」的信息，终端文本对按库分组的
多维报告已显吃力。ADR-0002 定调本地 Web 为薄报告层：`modou ui` 起本机服务渲染
既有报告 JSON，无登录无部署（lazygit 模式）——价值在渲染不在服务，做厚即变成
自己反对的平台。本 change 落地后 v0.4 三刀收齐，UI 消费全部四类车道报告。

## What Changes

- `modou ui`：传入一条或多条报告 JSON → 起本机服务并自动打开浏览器渲染；
  仅绑定回环地址（拒绝外部绑定参数）；无账号无登录。
- 视图四类：验收（按库分组三类结论与维度明细）、优化（建议两级状态与执行计划
  前后对比）、审核（命中清单）、巡检（漂移 / 未用索引 / 慢日志聚合榜）。
- 前端源码独立目录 + Node 24 工具链构建（CI 预留的 ui 门禁 job 自本 change 起
  激活）；构建产物随 Python 包分发——运行期零 Node 依赖。
- 报告只读：不提供任何写操作；页面资源全部本地，零外部网络请求。

## 受影响决策

- ADR-0002：本地 Web 为薄报告层、仅监听 localhost、无登录无部署；UI 不承载
  业务逻辑（渲染是唯一职责）。
- CI 形态（architecture.md）：ui 门禁为 Node 24（家族 web 门禁标准），
  `ui/` 落地即接管 typecheck/lint/test。

## 顺序与依赖

- 前置：v0.4 lint / patrol 先行落地（UI 消费其报告形态，视图契约才有实物可对）。
- 不依赖 MCP 表面；报告文件格式契约（docs/formats.md）是唯一耦合点。

## 不做清单（Non-goals）

- 不做编辑、重跑、修复入口（操作回 CLI/MCP，渲染是唯一职责）。
- 不做历史趋势、对比留档与本地状态存储（不落任何状态文件）。
- 不做鉴权、多用户、远程访问（回环地址是边界）。
- 不做服务端部署形态与配置管理（零平台化红线 3）。
- 不做报告内容的二次计算或再判定（只呈现报告已有结论）。
