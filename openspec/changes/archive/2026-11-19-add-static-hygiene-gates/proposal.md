# 提案：静态卫生收口（命名规则启用；S/D/死代码/全限定名评估结案）

## Why

结构门禁落地后仍有一组「PMD 类比」规则未决：命名规范、安全规则组、文档字符串、
死代码扫描、全限定名。逐项在默认参数下实测（2026-11-19，`src/modou`），需要
一次给出可执行结论，避免留下无限期待办。

## 实测与决策

| 规则组                    | 实测命中                                                            | 结论                                        |
| ------------------------- | ------------------------------------------------------------------- | ------------------------------------------- |
| ruff `N`（pep8-naming）   | `src` + `tests` 0 条                                                | **启用**（零成本）                          |
| ruff `S`（flake8-bandit） | `src` 8 条（S603×3、S608×2、S310×2、S105×1）；`tests` 另有 S101×855 | **不启用**                                  |
| ruff `D`（pydocstyle）    | `src` 546 条（D400/D415 共 460 条标点，缺 docstring 约 50 条）      | **不启用**                                  |
| vulture（60% 置信度）     | `src` 34 条                                                         | **不启用**                                  |
| 全限定名误用              | 人工审计 0 条                                                       | **不设门禁**（Python 生态无主流自动等价物） |

不启用理由（均非「留待以后」，而是本批结案）：

- **S**：`S608` 命中的是 `SHOW CREATE TABLE` / information_schema 查询的标识符
  拼接，是数据库工具的产品行为；`S101` 在测试中是常规断言。组内无法在不加
  `# nosec` / per-file ignore 的前提下零命中——按「零豁免」原则整体不启用。
- **D**：默认组要求句末英文标点，与现有中文文档风格（句号「。」）冲突；补齐
  460 处标点与约 50 条 docstring 属机械样板，违背「不写不必要文档」的仓库约定。
- **vulture**：34 条中绝大多数是 Typer/MCP 按名称动态注册的命令、dataclass 字段
  与框架回调；消除它们需要白名单（即豁免）或误删公共入口。真实死代码（未用
  import / 局部变量）已由 ruff `F401/F841` 覆盖。

## What Changes

- `pyproject.toml` ruff `select` 增 `N`。
- `AGENTS.md` 不变（N 随既有 ruff 步骤执行）。
- 其余四组不做配置变更；本 change 作为决策记录与证据留档。

## 不做清单（Non-goals）

- 不引入 bandit、pydocstyle、vulture 作为独立门禁。
- 不添加任何 `# nosec`、`# noqa`、per-file ignore。

## 风险

- 命名规则对未来代码生效：现有代码零命中，无迁移成本。
