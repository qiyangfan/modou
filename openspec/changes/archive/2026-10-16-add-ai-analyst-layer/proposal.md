# 提案：v0.5 第一刀——AI 分析师层（确定性工程 × AI 混合架构）

## Why

v0.2~v0.4 把宪法红线 1（"AI 只当顾问"）落地成了 AI 边缘化：四车道里 AI 仅在
optimize 承担候选生成，lint / patrol / verify 三车道零参与，未配 BYOK 三元组时
产品行为与无 AI 完全相同。owner 2026-10-16 定调纠偏：产品理念参照
alibaba/open-code-review（OCR）——**代码为主**（确定性层供证据、省 token、保精度），
**AI 承重**（做规则表达不了的语义判断，跳出 LSP 级纠错）。决策全文见 ADR-0009，
本 change 是其落地纵切面与能力契约冻结。

## What Changes

- **决策与文档面**：ADR-0009 成文、宪法红线 1/4 改写、architecture.md 增
  "AI 分析师层"章节与车道矩阵、goals.md 增 v0.5 里程碑、竞品事实库增补 OCR
  （本 change 内完成）。
- **结论分级契约**：报告扩列"AI 观点"区——单列展示、附来源标注、永不影响退出码；
  v0.1 冻结的报告契约只增不改。
- **委托面（通道 A，零密钥主通道，P0）**：MCP 扩列证据原语工具（快照摘要 /
  回放验收 / 三方 diff / EXPLAIN / lint 命中），每个工具与 CLI 机读出口对齐
  （parity 守护延伸）；随包分发 skills 资产，教宿主 Agent 组合工具完成数据库
  变更评审工作流。
- **BYOK 内置分析（通道 B，未配置零网络，P1）**：lint 残留语句语义评审（规则
  长尾）、verify 失败归因解释、patrol 跨信号综合叙事；形态为受控多轮——证据由
  确定性流水线预取打包，非 AI 自主调工具。
- **内核模块 `ai/`（P1/P2）**：schema 切片器、变更分包器、规则注入器、提示词
  模板、BYOK 客户端（自 optimize/advisor.py 演进收拢），与解析器同规格。
- **optimize 顾问升级（P2）**：从 one-shot 候选 dump 升级为受控多轮（EXPLAIN
  事实预取打包），实证关不变。
- **评测基线（P2）**：AI 观点抽样评测集入库，提示词/模板变更必跑评测。

## 受影响决策

- ADR-0003：AI 职责面修订为"AI 当分析师"（裁判、实证关、退出码条款原样保留），
  修订记录见 ADR-0009。
- ADR-0002：MCP 面从"1:1 映射 CLI"延伸出证据原语扩列——每个工具仍有 CLI 对应物，
  契约是延伸不是破坏。
- ADR-0006：`ai/` 上下文工程进内核库；AI SDK 依赖继续留在 optional-dependencies，
  内置通道用 stdlib HTTP（现有 advisor 模式推广）。
- ADR-0001：承诺四"本地优先 + Agent 原生轻端"的本兑现；不触碰任何 Non-goals。

## 顺序与依赖

- P0：结论分级契约 + MCP 证据工具 + skills 资产——零密钥先兑现 AI 赋能；
- P1：`ai/` 上下文工程模块 + lint 残留评审 + verify 归因 + patrol 叙事；
- P2：optimize 受控多轮升级 + 评测集回归机制。
- 前置：v0.2~v0.4 已归档（影子库基建、lint 规则引擎、MCP parity 均已就位）。
- 本 change 是**能力级纵切面**（ai-analyst 一个能力域，spec 契约一次冻结）；
  实施时若单 change 体量过大，可按 P0/P1/P2 拆为后续 change，契约不变。

## 不做清单（Non-goals）

- 不做内置 tool-use agent loop（AI 自主调用工具）——演进位，触发条件见 ADR-0009；
- 不做内置子代理编排——并发用确定性分包后的并发单轮调用等价实现；
- 不改报告 v0.1 冻结契约的既有字段与退出码语义（只增"AI 观点"区）；
- 不做 AI 自动修复器/自动改写执行——建议以附注呈现，执行永远在用户手里；
- 不做多模型路由、模型编排平台（零平台化红线）；未配置 BYOK 时零网络请求的
  既有承诺不变；
- 不做 PostgreSQL 方言的 AI 分析（ADR-0005，MySQL 先行）。
