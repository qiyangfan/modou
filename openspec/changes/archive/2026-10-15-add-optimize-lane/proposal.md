# 提案：v0.2 优化车道纵切面（optimize）

## Why

v0.1 变更车道已把影子库基建（快照/回放/报告）跑通，本 change 复用同一基建交付第二条
车道：慢 SQL 的优化建议必须过影子库实测复核才能声称有效（ADR-0003 实证关）。这是
MySQL 侧的空白生态位——PG 侧「AI 建议 + 实证」已被 HypoPG 路线占住，MySQL 无假想
索引等价物，真建索引实证既是成本也是壁垒（ADR-0005）。

调研结论（依据见 design.md）：结构快照无数据时优化器按空表估计（扫描行数下限钳制为
1），代价对比必然失真——采样数据采集是本 change 的前置攻坚项，不是可选项。

## What Changes

- 快照采集新增可选采样模式：确定性抽样、只读、低成本索引顺序读；快照格式升
  `format_version=2` 并向后可读（v1 契约不动）。
- 影子灌入扩展：数据行灌入 + 统计对齐口径（灌入后与建索引后各自显式刷新统计）。
- `modou optimize`：慢 SQL（SELECT/UPDATE/DELETE）+ 采样快照 →
  规则初筛（确定性候选与发现）→ AI 诊断（BYOK 可选，未配置零联网）→ 影子库实测判定。
- 副作用检查：冗余索引（前缀重叠三情形）、单表索引数上限、写放大提示。
- 报告两级状态：每条建议处于且仅处于「实测提升（附数据）」或「未验证（附原因）」；
  文本 + JSON 双出口；退出码 0/2（建议性输出不使用 1）。

## 受影响决策

- ADR-0003：AI 只当顾问；建议未过实证关不得以有效面目进报告，退出码不受 AI 输出影响。
- ADR-0004/0006：实证在影子回放环境中进行，复用 v0.1 基建，不引入第二解析器。
- ADR-0005：MySQL 先行；采样子集策略是本车道既定攻坚项。
- ADR-0008：多库默认，报告按库分组。

## 顺序与依赖

- 前置：v0.1（已归档）。
- 后续：v0.3 MCP 表面将把 optimize 纳入 1:1 工具清单与 agent 演示链路。

## 不做清单（Non-goals）

- 不做慢日志文件解析与指纹聚合（v0.4 patrol 车道）。
- 不做建议自动应用与任何生产写入（报告是唯一产物，全程对生产零写操作）。
- 不做全量数据复制（采样有每表行数上限，可配置）。
- 不做 DDL/表结构重设计建议（索引与查询改写为主）。
- 不做 PostgreSQL（ADR-0005）。
- AI 不产出结论：解释与候选生成之外无职责。
