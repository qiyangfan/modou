# 设计：v0.2 优化车道

> 技术口径依据 2026-10 调研（MySQL 8.0/8.4 官方手册核实，出处见文末）。

## 1. 采样数据是实证的前置（本 change 最大增量）

MySQL 优化器对空表按扫描行数 1 估计（0 行下限钳制），纯结构快照灌出的影子库上
建索引前后代价无差异——「实测提升 X%」不可能在空库上兑现。ADR-0005 已把采样子集
列为优化车道攻坚项，本 change 落地它。

- **抽样方式**：按主键索引顺序取每表前 N 行（索引顺序读，对线上低成本），
  确定性要求：同库同参数重复采集得到相同样本集。
  **实现决策（评审期修正）**：N 为 opt-in（`snapshot capture --sample-rows`，
  未给定时纯结构采集）而非「默认 10000」——默认采样会改变 v0.1 结构采集的
  隐私面与快照体积契约；optimize 在输入校验处要求采样快照并指引重采，
  达到同一证据前置目的且不扩大默认行为面。
- **已知偏差**：时间序主键下样本偏「早期数据」，报告须附实证环境数据规模声明
  （每表采样行数与全表估计行数）。哈希步进均匀抽样需全表扫描，列为后续增强，
  不进首发。
- **快照体积**：数据行内嵌快照 JSON（10k 行 × 典型行宽 ≈ 数 MB/表），本地文件可接受；
  行数元信息入快照。
- **格式演进**：`format_version` 1→2，新增可选数据节；v1 快照必须仍可读（verify
  照常），向后可读是冻结契约的演进方式（docs/formats.md）。`optimize` 要求采样快照
  （v1/无数据 → 输入错误退出 2 并指引重采）：纯规则审核属 v0.4 lint 车道，车道边界
  不许糊。

## 2. 代价判定口径

- **判定指标**：`EXPLAIN FORMAT=JSON` 顶层 `query_block.cost_info.query_cost`
  （估计代价）与扫描行数；辅助 `EXPLAIN ANALYZE`（TREE 格式，真实执行）的实测耗时
  作参考信息，不参与判定。
  - 两个已核实的事实口径：EXPLAIN ANALYZE 至 8.4 仍不支持 FORMAT=JSON（ERROR 1235）；
    `query_cost` 字段官方手册未正式文档化（源码行为 + 社区考据），解析须容错降级。
- **统计对齐**（两个已证实的坑）：
  1. InnoDB 持久统计是随机采样产物（random dives，官方明示重复 ANALYZE 可得出不同
     基数）→ 判定流程固定为「灌入后 ANALYZE → 基线 EXPLAIN → 建索引 → 再 ANALYZE →
     复测 EXPLAIN」，两侧各自显式刷新拉平口径；影子库调大
     `innodb_stats_persistent_sample_pages`（64~128）换统计稳定。
  2. ADD INDEX 无条件刷新该表索引统计（无视 auto_recalc）→ 建索引后必须再 ANALYZE，
     不得复用建前统计。
- **提升幅度** =（基线代价 − 复测代价）/ 基线代价。判定：代价下降方为「实测提升」；
  持平或上升 =「未验证（代价未降低）」。报告附「统计为采样估计，无官方同值保证」声明。

## 3. 载荷边界（红线 4 落地）

AI 端点配置时，发送载荷限于 SQL 文本与 schema 摘要（表/列/索引元数据），**不含任何
数据行**——采样数据只进本地影子库。未配置端点（配置三元组缺一即视为未配置）时不发起
任何网络请求，规则层照常产出候选（测试以网络层 mock 断言零外呼）。

## 4. 分层与依赖

- **规则初筛**（确定性，sqlglot）：WHERE/JOIN/ORDER BY 列提取 → 索引候选（含覆盖
  索引判断）+ 少量确定性发现（前导通配符、列上函数、OR 等值、无 WHERE 等）。规则
  「发现」是事实陈述（如「前导通配符使该条件无法走索引」），不需要实证；「建议」
  （索引 DDL/改写）无论规则还是 AI 来源，一律过实证关才可标提升——两级状态是全局
  统一口径，不给规则来源开口子。
- **AI 顾问**（可选依赖组 `[ai]`，OpenAI 兼容端点 + BYOK 凭证经环境变量）：候选生成
  与差异解释；超时/解析失败降级丢弃该候选（fail-safe），不阻塞报告。
- **副作用检查**（确定性，纯元数据）：
  - 冗余索引三情形（对齐 `sys.schema_redundant_indexes` 语义）：列集合相同 /
    非唯一索引列序列为另一索引前缀 / 唯一索引前缀使更长索引冗余；唯一性语义不可丢
    （非唯一索引被更长索引覆盖才判冗余）；外键依赖索引排除（联查
    `REFERENTIAL_CONSTRAINTS`/`KEY_COLUMN_USAGE`）；函数索引/表达式索引按
    `EXPRESSION` 比较，不能只看列名。
  - 单表二级索引数上限（默认 10，可配）；每新增一个二级索引附写放大提示。
- **实证管线**：候选逐一执行「基线 EXPLAIN → 建索引 → ANALYZE → 复测」，候选间回滚
  （DROP INDEX）或独立影子环境；影子环境失败 → 该建议「未验证（环境原因）」，管线
  不中断、整体退出码不受影响。

## 5. 退出码

- 0 = 报告产出；2 = 环境或输入错误（快照不可读/非采样快照、输入含 DDL、容器不可用等）。
- 1 不使用：优化是建议性输出，不构成验收结论（与 capture 同理；ADR-0003——退出码
  永远不受 AI 输出影响）。

## 6. 报告契约

- optimize 报告为独立格式（自带 kind 与版本），**不改** verify 的 report_version=1
  冻结契约；人读文本 + 机读 JSON 双出口同 v0.1 口径。
- 建议条目必含字段：来源（规则/AI）、语句指认、建议内容、状态（实测提升/未验证）、
  实证数据（前后代价、扫描行数、提升幅度、实测耗时参考）或未验证原因、副作用附注。
- 实现期将格式细节冻结进 docs/formats.md（惯例同 v0.1）。

  innodb-persistent-stats（采样页默认 20、ADD INDEX 刷新统计、auto_recalc 异步）、
  sys-schema-redundant-indexes（冗余三情形源码语义）
