# 项目宪法（modou）

墨斗——数据库工程化的本地层：变更验收 · SQL 优化 · 规则审核 · 漂移洞察。
产品存在的理由只有一句话：让"数据库变更是否落对、优化是否有效"从经验判断变成机器证据，
以实证约束下的 AI 分析放大其判断力，且**不要求用户改造任何发布流程**。
架构北极星见 `docs/architecture.md`；每项决策的完整论证见 `docs/adr/`（ADR-0001~0009）。
本文是代码评审的基线；与根 `AGENTS.md` 铁律冲突时以 AGENTS.md 为准。

## 不可协商的红线

1. **确定性代码当裁判，AI 当分析师**（ADR-0003/0009）：结论级判定——schema 是否
   一致、索引是否有效、规则是否命中——只出自确定性代码与影子库实证，退出码永不受
   AI 输出影响。AI 深度参与四车道的判断性工作（语义评审、归因解释、综合洞察、候选
   生成），产物一律两级标注：**实证已验证**（判定出自确定性代码与实测，可关联退出码）
   与 **AI 观点**（报告单列，永不影响退出码；优化建议未过影子库实测不得称"有效"）。
   这是产品信誉底线——裁判必须可审计，分析师必须可辨认，一个"AI 说有效就写有效"的
   工具，第一次误判就失去团队信任。
2. **回放推导，不靠解析拼终态**（ADR-0004）：期望态只能由真实数据库回放变更集得出；
   DDL 解析只服务于风险预警，任何"结论级"输出不得依赖解析器的正确性。
3. **零平台化**（ADR-0002）：禁止服务端部署形态、账号体系、常驻守护进程、审批工作流；
   报告 UI 仅监听 localhost。引入任何需要运维的组件 = 变成自己反对的东西。
4. **数据不出本地**：schema 快照、SQL 文本、慢日志只在本机或用户显式指定的环境处理；
   遥测默认关闭。AI 赋能有两条通道：内置分析走用户自配端点（BYOK），未配置时不发起
   任何网络请求；宿主 Agent 委托面（MCP 证据工具 + skills，ADR-0009）零密钥可用，
   数据同样不出本地。
5. **多实例多库默认**（ADR-0008）：单库假设的代码视为缺陷；命令域按多库清单工作，
   "只有一个库"必须是显式配置而非隐式前提。
6. **门禁即法律**：`uv run ruff format --check . && uv run ruff check . && uv run pytest`
   全绿是合入前提；回放/diff/优化行为的改动必须附实证记录。跑不过门禁的"完成"
   一律视为未完成。

## 工程口径

### 代码

- Python 3.12+，uv 管理，src 布局；新增代码必须带类型注解。
- sqlglot 是唯一 SQL 解析器；禁止引入第二套解析依赖。
- 重依赖（容器编排、AI SDK 等）一律放 optional-dependencies；核心保持秒级安装。
- AI 上下文工程（提示词模板、schema 切片、变更分包、规则注入）与解析器同规格：
  进内核库、类型注解、测试先行；AI 观点质量用评测集回归，提示词/模板变更必须重跑
  评测（ADR-0009）。
- 中文注释、中文文档、中文提交信息；日志与 CLI 错误码文本用英文。

### 测试

- 回放/diff/优化类任务测试先行：先写失败测试再实现（openspec rules 同源）。
- 影子库集成测试用容器 fixture，禁止依赖开发者本机手工起库。
- DML 数据订正不做全表比对：行数 + checksum 抽查是口径，不是妥协。

### 变更集

- 目录命名 `V<序号>__<描述>.sql` 向 Flyway 靠拢（ADR-0007）：流程放开时可平滑迁移
  标准迁移工具。
- `pack` 产物必须附带破坏性预警（DROP/TRUNCATE/大表 ALTER 与锁风险）；预警缺失视为缺陷。
